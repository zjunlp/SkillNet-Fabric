# Planner Prompt Quality Design

## Goal

Improve the public SkillFabric execution Planner so its handoff consistently helps the downstream
executor complete the original task. The Planner should produce short, task-directed plans that
preserve hard requirements, assign selected Skills only where useful, avoid unsupported
implementation details, and end with checks tied to concrete deliverables.

The change applies to the shared Planner in `skillfabric-ai`. Product callers, SkillsBench, and
AgentSkillOS inherit the behavior through `SkillFabric.plan()`. No experiment-only prompt override
will be added.

## Evidence

Sixteen manually revised SkillsBench prompts reduced generated plans from roughly 1,900-4,200
characters to roughly 1,100-1,800 characters while retaining exact outputs, decisive methods, and
task-specific checks. The repeated weaknesses were:

- restating the original task and Skill sources;
- expanding a selected Skill into an unnecessarily long procedure;
- proposing multiple approaches or speculative low-level implementation details;
- adding generic setup, fallback, and verification guidance already supplied at runtime;
- allowing the plan itself to encourage executor overwork.

The design follows Anthropic's public prompt-engineering guidance: clear and direct instructions,
an explicit role, separation of instructions from untrusted data, an exact output contract, a
representative example, and constraints against unsupported claims.

## Prompt Contract

Retain the current system/user separation, XML boundaries, untrusted-input rendering, and exact
JSON response schema. Rewrite the system contract around five requirements:

1. The original task is authoritative. Preserve literal output paths, filenames, formats,
   quantities, ordering, and acceptance constraints.
2. Produce one primary execution path. Use a selected Skill only when it contributes a decisive
   method or constraint, assign it one clear role, and mention its exact Skill ID once.
3. Include only specifics grounded in the original task or selected Skill context. Do not invent
   thresholds, algorithms, libraries, commands, parameters, dependencies, or extra deliverables.
4. Prefer the shortest complete plan: target outcome first, normally three to six ordered steps,
   then only task-specific checks for likely failure points.
5. Keep the handoff normally within 150-350 words. Permit up to roughly 500 words only for genuinely
   complex multi-artifact work.

Add one short positive example showing the desired outcome-first, ordered, artifact-specific form.
The example must be domain-neutral, use placeholder filenames, and demonstrate style without
introducing a mandatory section template.

## Boundaries

The change will not modify:

- route construction, Wiki exploration, or selected Skill context;
- `planner_output_json_schema()` or execution-package artifact structure;
- final executor prompt composition or runtime contracts;
- retry, telemetry, context limits, or LLM configuration;
- existing run artifacts.

Update `PLANNER_PROMPT_ID` so new Planner requests are distinguishable from requests generated by
the previous contract.

## Validation

Update unit tests to assert:

- the shorter adaptive word budget and one-primary-path requirement;
- source traceability for implementation details;
- explicit prevention of Skill-source restatement and speculative complexity;
- outcome-first steps and task-specific final checks;
- presence of the short positive example;
- unchanged exact JSON schema and execution-package rendering.

Run the focused orchestrator package tests and the broader `skillfabric-ai` unit suite if the
focused tests pass. No live LLM or benchmark call is required.
